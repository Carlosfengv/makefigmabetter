## 1. 背景

当前系统已经具备或计划具备设计文档编辑能力，但缺少统一的文档管理入口。

阶段 1.5 需要提供一个类似 Figma 文件浏览器的设计文档工作区。用户获得测试链接后，无需注册或登录，即可进入固定工作区，查看并管理其中的设计文档。

本阶段主要验证“从工作区找到文档、创建文档、进入编辑、保存并继续管理”的完整闭环。

## 2. Figma 参考说明

本阶段参考 Figma 的以下产品模式：

- 文件浏览器作为文档管理入口
- 最近使用、项目和回收站等导航结构
- 文件卡片及列表视图
- 文件名称搜索、筛选和排序
- 右键或更多菜单中的重命名、复制、移动和删除操作
- 删除后进入回收站，而不是立即永久删除
- 从回收站恢复文件
- 复制文件时生成独立副本，不继承原文件版本历史

参考资料：

- [Figma 文件浏览器](https://help.figma.com/hc/en-us/articles/14381406380183-Guide-to-the-file-browser)
- [Figma 文件与项目](https://help.figma.com/hc/en-us/articles/1500005554982-Guide-to-files-and-projects)
- [Figma 搜索文件](https://help.figma.com/hc/en-us/articles/4422774037271-Search-for-files-projects-and-people)
- [Figma 重命名文件](https://help.figma.com/hc/en-us/articles/360038511473-Rename-files-and-projects)
- [Figma 复制文件](https://help.figma.com/hc/en-us/articles/360038511533-Duplicate-or-copy-files)
- [Figma 删除与恢复](https://help.figma.com/hc/en-us/articles/360047512294-Delete-and-restore-files)

本需求只借鉴文件管理体验，不照搬 Figma 的团队、组织、权限、社区和多人实时协作能力。

## 3. 阶段定义

### 3.1 当前阶段

用户通过固定测试链接进入一个指定工作区，例如：

```text
https://test.example.com/workspace/{workspaceKey}
```

当前规则：

- 无登录页
- 无账号和密码
- 只有一个工作区
- 不支持切换工作区
- 所有获得链接的人拥有相同能力
- 所有访问者均可查看、创建、编辑和删除设计文档
- 不区分所有者、管理员、编辑者和查看者

`workspaceKey` 仅用于定位工作区，不视为正式权限控制。

### 3.2 阶段目标

阶段 1.5 需要完成以下闭环：

1. 通过链接进入工作区。
2. 查看工作区中的设计文档。
3. 创建新的设计文档。
4. 打开文档并进入设计编辑器。
5. 自动保存编辑内容。
6. 重命名、复制和整理文档。
7. 删除文档并从回收站恢复。
8. 在多个窗口访问时避免旧数据静默覆盖新数据。

### 3.3 成功标准

- 用户进入页面后，可以直接理解如何创建或打开文档。
- 创建文档后能够自动进入编辑器。
- 编辑内容保存后，刷新页面不会丢失。
- 返回工作区后，可以看到最新名称、缩略图和修改时间。
- 删除的文档可以从回收站恢复。
- 页面中不出现账号、成员和权限相关入口。

## 4. 用户与使用场景

### 4.1 目标用户

当前目标用户为获得测试链接的内部测试人员、产品人员、设计人员或研发人员。所有访问者统一称为“访问者”。

### 4.2 核心场景

#### 场景一：继续编辑已有文档

访问者打开工作区，通过缩略图、名称或搜索找到目标文档，打开并继续编辑。

#### 场景二：创建新文档

访问者点击“新建设计文档”，系统创建空白文档并进入编辑器。

#### 场景三：整理文档

访问者重命名、复制或将文档移动到项目中。

#### 场景四：处理无用文档

访问者将文档移至回收站，必要时恢复或永久删除。

## 6. 信息架构

```text
设计文档工作区
├── 最近编辑
├── 全部文档
├── 项目
│   ├── 项目 A
│   └── 项目 B
└── 回收站
```

### 6.1 最近编辑

展示当前工作区最近被打开或修改的文档。

### 6.2 全部文档

展示当前工作区中所有未删除的设计文档。

### 6.3 项目

项目用于对设计文档进行一级分类。本阶段支持多个项目，但不支持子项目；文档可以不属于任何项目。

### 6.4 回收站

展示已被软删除但尚未永久删除的文档。

## 9. 详细功能需求

### FR-01 进入工作区

访问者打开有效链接后：

1. 系统解析 `workspaceKey`。
2. 加载对应工作区信息。
3. 默认进入“最近编辑”。
4. 不进行登录状态校验。
5. 不展示登录页。

异常情况：

| 情况 | 页面反馈 |
| --- | --- |
| 工作区不存在 | 工作区不存在，请确认链接是否正确 |
| 工作区已停用 | 当前工作区已停止使用 |
| 网络异常 | 工作区加载失败，提供“重新加载” |
| 服务异常 | 暂时无法访问工作区，请稍后重试 |

验收标准：

- 有效链接可以直接进入工作区。
- 首次访问不要求输入任何身份信息。
- 刷新页面后仍停留在当前工作区。
- 无效链接不会进入空白或错误工作区。

### FR-02 查看文档列表

文档卡片展示：

- 缩略图
- 文档名称
- 所属项目
- 最近修改时间
- 更多操作按钮

列表视图展示：

- 文档名称
- 所属项目
- 创建时间
- 最近修改时间
- 文档状态
- 更多操作按钮

默认规则：

- 默认按照最近修改时间倒序排列。
- 已删除文档不出现在正常列表。
- 文档名称允许重复。
- 数据较多时使用分页或滚动加载。
- 最近编辑优先展示最近 20 个文档。

交互规则：

- 单击卡片：选中文档。
- 双击卡片：打开文档。
- 点击文档名称：打开文档。
- 点击更多按钮：打开快捷菜单。
- 触屏设备使用单击打开。

### FR-03 新建设计文档

操作流程：

1. 访问者点击“新建设计文档”。
2. 按钮进入加载状态。
3. 系统创建文档记录。
4. 默认名称为“未命名设计”。
5. 文档生成唯一 ID。
6. 创建成功后进入设计编辑器。
7. 编辑器加载空白设计内容。

归属规则：

- 从某个项目中创建时，默认属于当前项目。
- 从“最近编辑”或“全部文档”创建时，默认不属于任何项目。

防重复规则：

- 创建过程中按钮不可重复点击。
- 服务端需要防止同一个创建请求被重复执行。

失败处理：

- 创建失败时停留在工作区。
- 展示“创建失败，请重试”。
- 不在列表中保留无效文档。

### FR-04 打开设计文档

打开文档前，系统检查：

- 文档是否存在
- 文档是否属于当前工作区
- 文档是否位于回收站
- 文档是否已永久删除

正常情况下进入：

```text
/workspace/{workspaceKey}/design/{documentId}
```

| 情况 | 反馈 |
| --- | --- |
| 文档不存在 | 文档不存在或已被删除 |
| 文档在回收站 | 文档已进入回收站，请先恢复 |
| 文档已永久删除 | 文档已被永久删除 |
| 加载失败 | 文档加载失败，提供重试和返回工作区 |

打开成功后，更新文档的最近访问时间。

### FR-05 编辑与自动保存

工作区只定义编辑器接入和保存状态，不包含画布工具的具体产品需求。

保存规则：

1. 文档内容发生变化后触发自动保存。
2. 连续编辑时进行防抖合并。
3. 建议停止输入 800～1500 毫秒后保存。
4. 保存请求携带文档版本号。
5. 保存成功后更新版本号、修改时间和缩略图。
6. 离开编辑器后，工作区显示最新数据。

编辑器保存状态：

- 已保存
- 保存中
- 保存失败
- 离线
- 发生版本冲突

页面关闭前仍有未保存内容时，需要显示浏览器离开提示。

### FR-06 搜索文档

搜索范围：

- 文档名称
- 项目名称

搜索规则：

- 输入后约 300 毫秒执行搜索。
- 忽略英文大小写。
- 支持文档名称的部分匹配。
- 清空关键词后恢复当前页面的完整列表。
- 进入回收站后可独立搜索已删除文档。

无结果提示：

> 没有找到与“关键词”相关的设计文档。

同时提供“清除搜索”操作。

### FR-07 排序文档

支持：

- 最近修改：最新优先、最早优先
- 创建时间：最新优先、最早优先
- 文档名称：A–Z、Z–A

默认使用“最近修改，最新优先”。排序结果需要保证分页前后一致。

### FR-08 重命名文档

入口：

- 卡片更多菜单
- 右键菜单
- 列表中的名称
- 编辑器顶部名称

规则：

- 名称必填，长度为 1～100 个字符。
- 自动清除首尾空格。
- 名称允许重复。
- Enter 保存，Esc 取消，点击输入框外保存。
- 重命名不改变文档 ID 和访问地址。
- 重命名计入最近修改时间。
- 保存失败时恢复原名称并展示错误提示。

### FR-09 复制文档

操作结果：

- 生成新的文档 ID。
- 默认名称为“原名称 - 副本”。
- 副本保存在原项目。
- 复制当前文档内容和缩略图。
- 不复制原文档版本历史。
- 原文档和副本后续独立保存。

复制完成后，新文档出现在原文档附近并自动选中。

### FR-10 移动文档

操作流程：

1. 访问者选择“移动到项目”。
2. 系统打开项目选择弹窗。
3. 展示全部有效项目。
4. 当前项目置灰或标记为“当前位置”。
5. 选择目标项目并确认。
6. 系统更新文档所属项目。
7. 展示移动成功提示。

同时支持“移出项目”，将文档放回未分组状态。移动不改变文档 ID、链接和内容。

### FR-11 删除文档

本阶段删除采用软删除。

操作流程：

1. 访问者选择“移至回收站”。
2. 系统展示确认弹窗。
3. 确认后文档状态变为 `trashed`。
4. 文档从正常列表中移除。
5. 文档出现在回收站。
6. 页面展示操作成功提示。

确认文案：

> 确定将“文档名称”移至回收站吗？所有通过当前工作区链接访问的用户都将无法继续打开该文档。你可以稍后从回收站恢复。

成功提示提供短暂的“撤销”按钮，建议保留 8 秒。

### FR-12 恢复文档

- 原项目仍然存在时，恢复至原项目。
- 原项目已删除时，恢复为未分组文档。
- 恢复后保留原文档 ID。
- 原文档地址重新可访问。
- 恢复后状态变为 `active`。
- 恢复失败时，文档继续留在回收站。

### FR-13 永久删除

操作流程：

1. 访问者在回收站选择“永久删除”。
2. 系统展示二次确认弹窗。
3. 弹窗明确说明无法撤销。
4. 确认后彻底删除文档内容或进入服务端清理队列。
5. 文档从回收站消失。
6. 原文档链接永久失效。

确认文案：

> 永久删除“文档名称”？该操作无法撤销，文档内容也无法恢复。

Phase 1.5 不提供“一键清空回收站”。回收站文档建议保留 30 天；自动清理未实现前，不展示到期删除文案。

### FR-14 项目管理

项目支持：

- 新建项目
- 重命名项目
- 查看项目中的文档
- 删除空项目

规则：

- 项目名称必填，长度为 1～50 个字符。
- 项目描述选填，最多 200 个字符。
- 项目名称允许重复。
- 不支持子项目。
- 项目中存在文档时不能直接删除。
- 删除项目不应自动删除其中的文档。

### FR-15 视图切换

支持卡片视图和列表视图。当前设备需要记住最后选择的视图，可保存在浏览器本地，无需与服务端同步。

### FR-16 版本冲突保护

虽然当前没有账号，但可能有多个访问者或多个浏览器窗口同时编辑同一文档。

1. 文档初始版本为 `1`。
2. 保存请求携带当前版本号。
3. 每次保存成功，服务端版本号加 `1`。
4. 客户端版本落后时，服务端拒绝直接覆盖。
5. 编辑器提示文档已发生变化。
6. 用户可以重新加载最新版本。

提示文案：

> 该文档已在其他窗口发生变化。重新加载后可以继续编辑最新版本。

阶段 1.5 不实现内容自动合并和实时协作，但禁止静默覆盖较新的内容。

## 10. 文档状态

| 状态 | 说明 | 用户是否可打开 |
| --- | --- | --- |
| `creating` | 正在创建 | 否 |
| `active` | 正常状态 | 是 |
| `saving` | 正在保存 | 是 |
| `save_failed` | 保存失败 | 是 |
| `conflicted` | 发生版本冲突 | 受限 |
| `trashed` | 位于回收站 | 否 |
| `deleting` | 正在永久删除 | 否 |

界面状态不能只通过颜色表示，需要配合文字或图标。

## 11. 空状态与异常状态

| 场景 | 标题或提示 | 可用操作 |
| --- | --- | --- |
| 全部文档为空 | 还没有设计文档 | 新建设计文档 |
| 项目为空 | 这个项目中还没有设计文档 | 新建文档、移动已有文档 |
| 回收站为空 | 回收站是空的 | 无 |
| 搜索无结果 | 没有找到相关设计文档 | 清除搜索 |
| 列表加载失败 | 设计文档加载失败，请检查网络后重试 | 重新加载 |
| 缩略图失败 | 显示默认设计文档封面 | 仍可打开文档 |

## 14. 接口范围

Phase 1.5 至少需要以下能力：

- 获取工作区详情

- 获取最近编辑文档
- 获取单个文档
- 创建设计文档
- 保存设计文档
- 重命名文档
- 复制文档
- 移动文档
- 删除文档
- 获取回收站列表
- 恢复文档
- 永久删除文档
- 获取项目列表
- 创建项目
- 重命名项目
- 删除项目

列表请求统一支持：

- 页码或游标
- 每页数量
- 搜索关键词
- 项目 ID

所有创建、删除和复制操作需要防止重复提交。

## 15. 非功能要求

### 15.1 性能

- 页面基础结构在 1 秒内可见。
- 普通网络下文档列表在 2 秒内完成加载。
- 搜索交互在输入后 1 秒内返回结果。
- 大量文档使用分页、滚动加载或虚拟列表。
- 缩略图使用懒加载。

### 15.2 数据一致性

- 保存、重命名、移动和删除成功后，列表数据必须同步更新。
- 操作失败时不能错误地提前移除文档。
- 多窗口编辑必须通过版本号检测冲突。
- 创建和复制操作需要保证幂等性。

### 15.3 可用性

- 所有异步操作都有加载、成功或失败反馈。
- 危险操作必须确认。
- 键盘支持 Tab、Enter 和 Esc。
- 文字过长时截断，并通过悬停展示完整名称。
- 不依赖颜色单独传达状态。

### 15.4 测试环境安全

由于知道链接的人都可以操作全部文档：

- 页面明确标记“测试工作区”。
- 禁止存放正式或敏感资料。
- 工作区链接使用难以猜测的随机标识。
- 页面禁止被搜索引擎收录。
- 服务端限制异常频率和超大请求。
- 永久删除必须二次确认。
- 建议保留定期服务端备份。

以上措施只用于降低测试风险，不等同于正式权限系统。

## 17. 核心验收用例

### 17.1 工作区

- [ ] 有效链接无需登录即可进入。
- [ ] 无效链接展示正确错误状态。
- [ ] 页面不出现账号、成员和权限入口。
- [ ] 页面不提供工作区切换。

### 17.2 文档创建与查看

- [ ] 可以创建空白设计文档。
- [ ] 连续点击不会重复创建。
- [ ] 新文档刷新后仍存在。
- [ ] 可以从卡片和列表打开文档。
- [ ] 已删除文档不能从普通入口打开。

### 17.3 编辑与保存

- [ ] 编辑后自动保存。
- [ ] 保存时展示正确状态。
- [ ] 刷新后内容保持一致。
- [ ] 保存失败时提供明确提示。
- [ ] 多窗口使用旧版本保存时不会静默覆盖新版本。

### 17.4 文档管理

- [ ] 可以重命名文档。
- [ ] 可以复制文档，副本具有新 ID。
- [ ] 可以将文档移动到其他项目。
- [ ] 移动和重命名不改变文档链接。
- [ ] 可以将文档移入回收站。

### 17.5 回收站

- [ ] 删除后的文档出现在回收站。
- [ ] 可以恢复到原项目。
- [ ] 原项目不存在时恢复为未分组文档。
- [ ] 永久删除必须二次确认。
- [ ] 永久删除后原链接失效。

### 17.6 搜索与排序

- [ ] 可以按文档名称搜索。
- [ ] 清空搜索后恢复完整列表。
- [ ] 无结果时展示专用空状态。
- [ ] 各种排序方式结果正确且稳定。

### 18.1 产品与设计
